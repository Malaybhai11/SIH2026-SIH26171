🎯 Aavaran red-team suitesynthetic PII only — evasion techniques a real page might use
1. Split-node PII
Aadhaar and email split character-by-character across sibling <span> tags — a common scraper-evasion trick. Tests whether text-block grouping reassembles it before scanning.
 2. Sub-pixel / tiny font
PII rendered at 2px and 0.1px — still in the DOM and readable by a model that reads text, not pixels. Tests whether tiny rendered size drops the pixel redaction box.
 3. Rotated / skewed text
PII under a CSS transform (rotate, skew, 3D). getClientRects() should still return an axis-aligned box that covers it.
 4. SVG-embedded text
PII inside an <svg><text> element — real, selectable DOM text, but outside the normal text-node walk most extractors use.
 5. Canvas bitmap text
PII drawn onto a <canvas> as pixels — no text node exists at all. This is exactly what on-device OCR (A1) is for; expected to leak until then.
 6. Homoglyph substitution
An email using a Cyrillic "а" instead of Latin "a". A known, documented limit of character-class regex — not fixed here.
 7. Hidden agent instructions
Invisible text instructing the agent to leak data or take an unrelated action. Baseline for B2 (prompt-injection shield) — not a redaction test.
